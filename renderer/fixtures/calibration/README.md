# Renderer calibration fixture v1

Isolated 12-second analytic choreography, generated by `npm run generate:calibration` in `renderer/`. It does not run or modify the simulator. `match_info.json` follows the shared metadata contract and reuses fictional sample rosters; only home players 8 (A) and 10 (B) appear in tracking. `tracking.jsonl` has 300 consecutive frames at 25 FPS, timestamps 0–11.96 s. No randomness is used.

| Time (s) | Action |
| --- | --- |
| 0–2 | A stationary near (55,25) with ball alongside; B waits at (72,30). |
| 2–4 | Ball passes from (55.75,24.25) to (72.75,29.25), with a low 0.18 m arc above its rolling center height. |
| 4–5 | B receives and holds. |
| 5–8 | B carries 15 m goalward and 4 m across the pitch at about 5.2 m/s. |
| 8–9 | Shot travels to (106,34), with peak center height 0.91 m. |
| 9–12 | Ball rests inside the net; players hold. |

Coordinates remain in meters, bottom-left pitch origin; ball height is its center above grass. The shot crosses x=105 inside the 7.32×2.44 m goal mouth and stops at x=106 (within the 2 m goal depth). This intentional goal-area extension is the only out-of-pitch ball position. There is no goalkeeper in this baseline, so save/occlusion evaluation should use other sequences.

`ground_truth.events.json` follows the existing shared event schema: pass at 2 s, shot at 8 s, and goal at the analytically computed goal-line crossing. `source: sim` denotes synthetic ground truth, not video detections; these are generated fixture labels, not real simulator output. Numbers are computed from the trajectory. The renderer and export commands load **only** metadata and tracking, never this file. Give only the video to the vision model; use this truth separately for scoring.

Run repository schema validation explicitly: `.venv/bin/python scripts/validate.py renderer/fixtures/calibration` from the repo root. The shared validator's default paths do not include renderer fixtures.
