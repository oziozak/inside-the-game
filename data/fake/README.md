# Fake data

Synthetic sample data so everyone can build before the real simulator and vision AI work. Everything here is generated by `scripts/generate_fake_data.py` (seeded, so it is the same every time). **Do not edit these files by hand**; change the script and regenerate.

| Folder | What it is | Use it for |
| --- | --- | --- |
| `sample_a/` | Short match, 2 x 5 minutes, ~120 events. **Every event type appears at least once**, including a goal, a red card, a penalty or direct free kick, substitutions and offside. | Agents and web player development: every graphic and explanation has something to trigger it. |
| `sample_b/` | Full match, 2 x 45 minutes, ~1,150 events. Event counts match real-football norms (passes, shots, corners, fouls...). | Realism, performance, the director's screen-time budget, stats code. |

Files:

- `match_info.json`: teams, kits, lineups, formations, and when each half starts and ends.
- `events.json`: all events, sorted by `t`. All have `"source": "sim"`.
- `tracking.jsonl` (sample_a only): positions of all players and the ball, 25 fps, **first 60 seconds**.
- `overlays.json` (sample_a only): template overlays standing in for the director agent, in `analyst/en`, `casual/en` and `casual/tr`.

Full 25 fps tracking for both matches is too big for git (~150 MB). Generate it locally:

```bash
python scripts/generate_fake_data.py --full-tracking
# writes data/generated/sample_a/tracking.jsonl and data/generated/sample_b/tracking.jsonl
```

Checks the generator passes:

- Over 40 simulated matches, every event type averages inside its real-football range (about 900 passes, 23 shots, 2.8 goals, 11 corners, 19 fouls per match, 81% pass accuracy). Run `--report` to see it.
- Top player speed is about 10.8 m/s (a sprint); nobody teleports, except at the half-time cut.
- At about 98% of passes and shots, the player nearest the ball is the one who plays it, so "nearest player has possession" works for the vision AI's event rules.
- Set-piece takers stand at the ball when they take it.
